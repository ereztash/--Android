# M0 — Scaffold, CI, network gate

Written **before** any M0 work began, per the build rule "do not begin until that is written".

## Scope

1. Gradle multi-module scaffold: Kotlin DSL, version catalog, JVM target 17, minSdk 30,
   targetSdk 36, compileSdk 36.
2. Module split chosen so that the *decidable* logic is testable on this host without a
   device: a pure-JVM `:core` holds the lexicon, correction and sensitive-field logic; the
   Android modules hold only the parts that genuinely need a device.
3. CI that runs on every push.
4. **GATE-NET-1**: the no-network gate, with a committed positive control.
5. **GATE-DENOM-1**: a zero-denominator guard, with a committed positive control.
6. **GATE-IMS-1**: static ban on overriding `onCreateInputMethodSessionInterface` (§1.6),
   with a committed positive control.
7. `docs/LICENSES.md`, `docs/OPERATOR_NOTICES.md`, `docs/VERIFICATION.md`, initial
   `docs/QA_MATRIX.md`.
8. The minSdk 30 tradeoff, stated to the operator.

## Gates closed in M0, and the positive control committed for each

| Gate | What it asserts | Positive control (committed, runs in CI every push) | Expected control result |
|---|---|---|---|
| GATE-NET-1 | No network capability anywhere: no network permission in any manifest, no network-capable dependency coordinate, no network API in any source file | `tools/positive_controls/network/` — a manifest with `android.permission.INTERNET`, a Kotlin file using `java.net.HttpURLConnection` + `okhttp3`, and a coordinate file listing `com.squareup.okhttp3:okhttp` | gate exits **non-zero**, reporting exactly 3 findings across 3 detectors |
| GATE-DENOM-1 | The gate refuses to report "clean" when it examined nothing | run GATE-NET-1 against an empty directory | gate exits **non-zero** with `ZERO_DENOMINATOR`, never `PASS` |
| GATE-IMS-1 | No override of `onCreateInputMethodSessionInterface` (§1.6 — compiles fine, `LinkageError` at runtime) | `tools/positive_controls/forbidden_api/PlantedSessionOverride.kt` | gate exits **non-zero** |

A gate is recorded PASSED only when its positive control has been *demonstrated red in the
same CI run*. `run_gates.py` enforces this: it runs each control and fails the build if a
control unexpectedly passes.

## Tests added

- `tools/gate_tests/test_gates.py` — asserts, for each gate: (a) clean tree ⇒ exit 0 with a
  non-zero denominator; (b) positive-control tree ⇒ non-zero exit with the expected finding
  count; (c) empty tree ⇒ `ZERO_DENOMINATOR` failure.

## Completion checks

- `./gradlew :core:test` runs green (denominator: number of tests reported).
- `python3 scripts/run_gates.py` prints, per gate, the denominator and the control result.
- The control output is pasted verbatim into the M0 report showing red.
- Commits are small and separated by concern.

## What M0 explicitly does NOT cover

- No APK/AAB is produced or scanned in M0. GATE-NET-1 at M0 scans *source, manifests and
  declared dependency coordinates* — not compiled bytecode. Bytecode/DEX scanning is a
  separate gate (GATE-NET-2) and is **not** closed here.
- No device or emulator is involved. Nothing about runtime behaviour is asserted.
- The dependency detector can only see coordinates Gradle resolves for the configurations it
  is asked about; it does not prove a dependency is network-free, only that it is not on a
  known-network blocklist. That limitation is printed by the gate itself.
