# M1 — Lexicon pipeline

Written **before** any M1 work began.

The build spec calls this "the only part with binary risk". It is done first, before the IME
service exists, so that a licensing or reproducibility failure surfaces now rather than at M8.

## Scope

1. `scripts/build_lexicon.py` — deterministic, checksummed, reproducing §2.2's recipe.
2. **GATE-LEX-1** reproducibility: source sha256 must match, and derived counts must land
   within ±1% of 102,239 / 298,162 / 355,587.
3. **GATE-LEX-2** determinism: two runs must produce a byte-identical artifact.
4. `scripts/build_heldout_corpus.py` — a genuinely held-out, hash-locked Hebrew corpus for
   measuring coverage, drawn from Hebrew Wikipedia (CC BY-SA 4.0).
5. `:core` Kotlin: `HebrewLexicon` (sorted UTF-8 blob + binary search) and `PrefixStripper`
   (the 79-string closed grammar), with JVM unit tests.
6. A coverage measurement over the held-out corpus at MIN_STEM ∈ {none, 2, 3, 4, 5},
   reported with denominators and the corpus hash beside every number.

## Why the held-out corpus is built by range-reading a multistream dump

Coverage must be measured on text that is **not** in the lexicon. Source B is in the lexicon,
so holding out part of it would inflate every number.

The obvious cheap approach — download the first N MB of `hewiki-*-pages-articles.xml.bz2` and
decompress the prefix — produces a biased sample: pages are ordered by ascending page id, so a
prefix is the *oldest* articles, skewed toward early core encyclopedic topics.

Instead: fetch `hewiki-20260801-pages-articles-multistream-index.txt.bz2` (9,754,245 bytes),
which lists `offset:page_id:title` for every page. Each multistream block is an independently
decompressible bz2 stream of ~100 pages. A fixed-seed deterministic selection of block offsets,
fetched by HTTP Range, gives an **unbiased sample across the whole encyclopedia** for a few MB
of transfer instead of 1.13 GB — and the selection is reproducible because the seed, the dump
date and the resulting corpus sha256 are all committed.

## Gates closed in M1, and the positive control committed for each

| Gate | Asserts | Positive control | Expected |
|---|---|---|---|
| GATE-LEX-1a | Source integrity: each source's sha256 matches the committed manifest | `tools/positive_controls/lexicon/corrupt_source_a.csv` — a source with one byte changed | build fails with `CHECKSUM_MISMATCH` |
| GATE-LEX-1b | Derived counts land within ±1% of the spec's | control fixture whose filter is deliberately wrong (drops final-form letters), yielding counts far below target | build fails with `COUNT_OUT_OF_TOLERANCE` |
| GATE-LEX-2 | The artifact is byte-identical across runs | `--nondeterministic` debug flag that emits set-iteration order instead of sorted order | determinism check fails with differing sha256 |

**The tolerance is fixed at ±1% by the build spec and is not mine to move.** If a count lands
outside it, the correct response is to report the conflict, not to widen the band. This is
recorded here before the numbers are known.

## Tests added

- `HebrewTextTest` — NFC + niqqud stripping, including the te'amim range and the
  punctuation code points that sit inside U+0591–U+05C7.
- `PrefixStripperTest` — the grammar generates exactly 79 non-empty strings, max length 5;
  the seven words §2.3 names (שמן, שולחן, מים, הר, לחם, שמש, ברזל) resolve as *literal*
  lexicon hits so the stripper never fires on them; MIN_STEM is respected.
- `HebrewLexiconTest` — binary search over the packed blob agrees with a reference `Set`
  on every one of a sampled subset, plus absent-word cases.

## Completion checks

- `python3 scripts/build_lexicon.py --verify` reproduces 102,239 / 298,162 / 355,587.
- Both GATE-LEX controls demonstrated red, output pasted into the M1 report.
- `./gradlew :core:test` green, with the test count stated.
- Coverage table reported with the corpus sha256 beside every row.

## What M1 explicitly does NOT cover

- **No accuracy claim.** Coverage (is this token in the lexicon?) is not correction accuracy
  (does the right candidate rank first?). Accuracy needs the golden corpus and is M5.
- **No thresholds are set here** beyond MIN_STEM's starting value, which the spec fixes at 4.
  Correction weights are explicitly deferred to M5, after a baseline exists.
- The held-out corpus is Wikipedia prose. It is not representative of *keyboard* input —
  no SMS register, no slang, no typos. Coverage measured on it is a claim about encyclopedic
  Hebrew, and is written that way.
- The lexicon is unvocalized surface forms only. Ktiv male/haser (§2.5) is untouched; no
  inflation factor is assumed because none has been measured.
