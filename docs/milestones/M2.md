# M2 — IME service, manifest, method.xml, onboarding

Written **before** any M2 work began.

## Scope

1. `:app` — the Android application module. minSdk 30, targetSdk 36, compileSdk 36.
2. `AndroidManifest.xml` with the service declaration §1.8 requires, exactly.
3. `res/xml/method.xml` with `suppressesSpellChecker`, `configChanges` and subtypes.
4. `HebrewImeService extends InputMethodService`, structurally correct:
   - reads initial context **once** from `EditorInfo` in `onStartInput` (§1.1)
   - maintains its own incremental buffer, resynced **only** from `onUpdateSelection`
   - never calls `getTextBeforeCursor` (enforced by GATE-API-1)
   - never overrides `onCreateInputMethodSessionInterface` (§1.6)
   - applies `navigationBars()` + `captionBar()` insets (§1.7)
   - holds no state in the input `View` (§1.5)
5. `InputContextBuffer` in `:core` — the buffer logic, pure JVM, fully unit-tested.
6. A Compose onboarding activity (Compose in settings only — §1.13).
7. **GATE-NET-2**: scan the *built* APK — merged manifest and DEX — for network capability.

## The API 30 problem, stated up front

`InputMethodInfo.getConfigChanges()` is **API 31** (measured; see `docs/VERIFICATION.md`).
minSdk is 30. So on API 30 devices the `android:configChanges` declaration in `method.xml` is
**not read at all**, and `onCreateInputView()` is re-called on every rotation, theme change,
locale change and density change.

Consequence: declaring `configChanges` is necessary but cannot be relied on. **No state may
live in the keyboard View.** That is not a style preference at minSdk 30, it is the only thing
standing between the user and a keyboard that forgets itself on rotation. GATE-IME-STATE-1
enforces it statically.

## Gates closed in M2, and the positive control committed for each

| Gate | Asserts | Positive control | Expected |
|---|---|---|---|
| GATE-MANIFEST-1 | The IME service declares `exported="true"`, `BIND_INPUT_METHOD`, the `android.view.InputMethod` action and the `android.view.im` meta-data; and `method.xml` sets `suppressesSpellChecker="true"` | `tools/positive_controls/manifest/` — a manifest with `exported` omitted, the permission dropped, and `suppressesSpellChecker` false | gate red on 4 rules |
| GATE-NET-2 | The **built** APK's merged manifest declares no network permission, and its DEX references no network class | A real `netcontrol` build type whose source set is `tools/positive_controls/apk_network/`, adding an INTERNET permission and `java.net.HttpURLConnection` usage. **An actually assembled APK**, not a simulated one. | gate red on both manifest and DEX detectors |
| GATE-IME-STATE-1 | No mutable state is declared in an input `View` subclass | `tools/positive_controls/ime_state/` — a View with a mutable field | gate red |

GATE-NET-2's control is deliberately expensive. Scanning a real APK and proving the scanner
catches a real defect requires building a real defective APK; a fixture that merely *looks*
like DEX would prove nothing about the scanner's ability to read DEX.

## Completion checks

- `./gradlew :app:assembleDebug` produces an APK.
- `python3 scripts/check_apk.py` reports clean, with denominators (permissions examined,
  DEX strings examined).
- `./gradlew :app:assembleNetcontrol` produces the defective APK and the gate rejects it.
- GATE-NET-1's manifest detector finally has a non-zero denominator, so GATE-NET-1 moves from
  PASS-PARTIAL to PASS.
- `./gradlew :core:test` green, test count stated.

## What M2 explicitly does NOT cover

- **Nothing is run on a device.** Enabling the IME in Settings, selecting it, and typing into a
  real editor are **NOT RUN** and are recorded that way in `docs/QA_MATRIX.md`. A manifest that
  merges correctly is not a keyboard that works.
- No key layouts, no glyphs, no touch handling — M3.
- No sensitive-field policy yet — M4. Until then the service must not persist or process
  anything, and does not.
- `onCreateInputView` re-entry on API 30 is *defended against* statically, but the defence is
  **not verified on a device**.
