# M9 — the mirrored keyboard

**Reported by the operator, from a phone:** *"צריך לשים לב שזה לא נראה כמו המקלדת הרגילה, כלומר
המקשים לא מסדרים באותה צורה, אלא כאילו זו מראה"* — the keys are not arranged the way a normal
keyboard is; it looks like a mirror.

They were right, and this was the first time any part of this project had been observed by a
human being.

## The bug

`Layouts.hebrew` carried `rtl = true`, and `KeyGeometry` mirrored every row when it saw that
flag. One root cause, four symptoms visible in a single screenshot: the letters ran backwards,
backspace sat on the left instead of the right, shift on the right instead of the left, and the
layout switch in the wrong corner.

The mistake is a conflation. Hebrew **script** is written right to left. A Hebrew **keyboard**
is not: SI-1452 maps letters onto the physical QWERTY key positions, which run left to right.

```
Q  W  E  R  T  Y  U  I  O  P
/  '  ק  ר  א  ט  ו  ן  ם  פ
```

On a phone, with `/` and `'` dropped, the top row is `ק ר א ט ו ן ם פ` — **left to right on
screen**. Two different things, one of them borrowed for the other.

## The part that matters more than the bug

I had written a test called `hebrewFirstKeyIsOnTheRight`, and it passed. It asserted the
mirrored behaviour as correct.

The wrong assumption sat in the implementation **and** in the assertion, so both agreed and
both looked green. No amount of positive-control discipline catches that: **a control proves a
check can fail, not that the check is asking the right question.** Every gate in this project
had been running for six milestones over a keyboard that could not be used, and none of them
could have said so.

## What replaced it

Tests written against the **external standard** rather than against the code:

| test | asserts |
|---|---|
| `hebrewLettersSitAtTheirQwertyPositions` | the literal SI-1452 sequence, transcribed from the standard |
| `hebrewFunctionKeysAreOnTheConventionalSides` | shift left, backspace right |
| `noLayoutIsMirrored` | model order equals screen order, for every layout |
| positive control | a deliberately reversed layout is fed in and must be rejected |

`rtl` is gone from key geometry entirely. What remains is `ScriptDirection`, which `KeyGeometry`
**never reads** — the name and its documentation exist so the next person cannot make the same
substitution by accident. Script direction still matters in exactly one place, the suggestion
strip, where the best candidate belongs where the eye starts.

## What this milestone changed about the method

Nothing in the gate architecture. The architecture was working; it was answering a question
nobody had checked the wording of.

What changed is a preference, applied from M9 onward and visible in every milestone after it:
**where an external authority exists, assert against the authority, not against a value read
out of the implementation.** M10's Unicode test checks all 55 code points of the Hebrew mark
range against `Character.getType` rather than a hand-written list, and found four
misclassifications. M10's sentence-boundary test reads the regex out of the Python builder
rather than restating it. M11's confusion pairs come from Hebrew phonology rather than from the
corpus they are scored on.

None of those would have been written this way before a user looked at a screenshot and said it
looked like a mirror.
